---
title: 3. 隔離の限界と過去の脆弱性
description: コンテナの隔離が破られる、3つの層
---

ここまでの隔離は、どれも Linux カーネルの機能を組み合わせたものでした。ということは、コンテナは必ずしも安全とは言えません。設定を間違えたり、ランタイムやカーネルの実装にバグがあったりすれば、隔離は破られてしまいます。ここでは、実際に起きた脆弱性を、破られ方ごとに見ていきます。講義では、この中の1、2件にだけ触れます。

## 破られ方の層

コンテナの隔離が破られるときは、次の3つの層のどこかに原因があります。

| 層 | 原因 | 例 |
| --- | --- | --- |
| 設定 | オプションなどの設定のミス | `--privileged`、`--pid=host` (前のページで見たもの) |
| ランタイム | `runc` などの実装のバグ | CVE-2019-5736、CVE-2024-21626、CVE-2025-31133 |
| カーネル | 共有しているカーネルのバグ | CVE-2026-31431 (Copy Fail)、CVE-2026-43284 (Dirty Frag)、CVE-2026-53362 |

## ランタイムの脆弱性

ランタイムは、第2章で自作した部分にあたります。実装の細かいミスが、そのまま脱出口になります。

- CVE-2019-5736: コンテナの中のプロセスが、`/proc/self/exe` を経由して、ホストにある `runc` 自身の実行ファイルを上書きできました。次に `runc` が実行されたときに、攻撃者のコードが、ホストの root 権限で動きます。
- CVE-2024-21626: `runc` の内部で、ホストのファイルを指すファイルディスクリプタが、コンテナの中のプロセスに漏れていました。それを使うと、作業ディレクトリがホストのファイルシステムを指して、ホストのファイルに触れました。
- CVE-2025-31133: ステップ 2 の (発展) で、`/dev/null` を `bind` マウントしたのを覚えているでしょうか。`runc` も、機密のパスを隠すために `/dev/null` をマウントするのですが、マウント元が本当に `/dev/null` かどうかを確認していませんでした。マウントの競合を突くと、ホストの `/proc` に書き込めて、コンテナの外に出られます[^1]。

## カーネルの脆弱性

こちらのほうが、より本質的な問題です。第2章で作った隔離は、全てカーネルの機能でした。コンテナはカーネルを共有しているのですから、カーネルの脆弱性は、そのままコンテナからの脱出につながります。

- Copy Fail (CVE-2026-31431): 2026年4月に公開された、カーネルの暗号 API の欠陥です。一般のユーザーが、ページキャッシュ (ファイルの内容をメモリ上にキャッシュしたもの) に、任意のデータを書き込めてしまいます。ページキャッシュはホスト全体で共有されているので、コンテナの中からも、ホストや他のコンテナと共有しているファイルの内容を書き換えて、root 権限を得られます[^2]。
- Dirty Frag (CVE-2026-43284): 2026年5月に公開された、Copy Fail の後継にあたる欠陥です。IPsec の処理にある欠陥で、同じようにページキャッシュを書き換えられます。悪用するには、user namespace や network namespace を作れることが前提になっています。ステップ 4 や 5 で使った機能が、攻撃の足がかりになることがある、ということです[^3]。
- CVE-2026-53362: IPv6 のフラグメントの処理にある欠陥で、コンテナの中から、ホストの root 権限に到達できます。こちらも、悪用するには network namespace を作れることが必要です[^4]。OpenAI の事件の報告書でも、エージェントがカーネルの脆弱性を使って、コンテナの外に出たことが書かれています[^5]。

そして、VM であっても、ホストのカーネルが仲介している以上、無敵ではありません。2026年10月に公開された PwnEscape (CVE-2026-99999) は、KVM の仮想マシンの中から、ホストのカーネルを攻撃して脱出できる欠陥でした。ホストのカーネルのネットワーク処理の誤りが原因です[^6]。

## 共有しているカーネル

同じカーネルを共有している限り、コンテナの隔離は、カーネルの欠陥に弱いままです。第2章で塞いだ穴 (namespace、cgroup、capability、seccomp) を、いくら並べ直しても、残るのは、共有しているカーネルそのものです。**コンテナの隔離は、ホストのカーネルが正しく動くことを前提に成り立っています。**
