応募課題の問いでは、Linux コンテナの基礎となるシステムプログラムに関する小問題を設けていました。

> Linux において、プログラムを実行するときに「プロセス」がどのように作られるかを調べて、自分の言葉で説明してください。
>
> その際、可能であれば fork、exec、clone、system call という言葉のうち、分かるものを使って説明してください。すべてを正確に説明できなくても構いませんが、どこまで理解したか、どこがまだ分からないかも書いてください。

この問いの出題は、必要な知識の事前学習という意味も兼ねていました。ここでは、出題の内容に対する解説と、システムプログラムに関する基礎知識の説明を行います。

### プロセスとは

プログラムは、ディスクに置かれた実行ファイルです。それに対してプロセスは、そのプログラムが実行されている状態で、OS が一つの単位として管理しています。プロセスには一意な ID が振られていて、これを PID と呼びます。プロセスには、PID、専用のメモリ空間、開いているファイル、実行ユーザー、親プロセスなどの情報が実行の状態として紐づいています。同じプログラムを2回実行すれば、プロセスは2つできることになります。

```sh
ps -o pid,ppid,comm
```

`PPID` が親プロセスの ID です。プロセスは必ず、いずれかのプロセスから作られます。

### システムコールとは

ファイルを開く、メモリを確保する、別のプロセスを作るなどの特別な操作は、プロセス自身では行えません。これらは、OS の中核であるカーネルが担当しています。

カーネルは、CPU、メモリ、ディスク、ネットワークといったハードウェアを直接管理し、複数のプロセスに安全に分け与える役割を持ちます。プロセスはハードウェアを直接操作できず、他のプロセスのメモリも勝手に覗けません。もしできてしまうと、一つのプログラムの不具合や悪意で、システム全体が壊れてしまうからです。

そこで、プロセスがカーネルの機能を使いたいときは、カーネルに依頼します。その唯一の入り口がシステムコール（syscall）です。`open`、`read`、`write`、`fork` などが、その例です。

```text
+--------------------------------------------+
|          プロセス（ユーザー空間）          |
|      例: シェル、ls、自作のプログラム      |
+--------------------------------------------+
              |  システムコール
              v
+--------------------------------------------+
|                  カーネル                  |
|   例: プロセス管理、メモリ管理、ファイル   |
+--------------------------------------------+
              |
              v
+--------------------------------------------+
| ハードウェア（CPU、メモリ、ディスク、NIC） |
+--------------------------------------------+
```

コンテナの隔離や制限も、カーネルが用意している syscall の組み合わせで実現されています。この講義で作るのは、その組み合わせです。

### プロセスはどう作られるのか

Linux では、主に2つの syscall を組み合わせてプログラムを実行します。

- `fork`：呼び出したプロセスの複製（子プロセス）を作る
- `exec`：今のプロセスの中身を、別のプログラムに置き換える

シェルで `ls` を実行すると、まずシェルが fork して自分の複製を作ります。次に、その子プロセスが exec して `ls` に置き換わります。親のシェルは、`ls` が終わるまで待ちます。

もう一つ、`clone` という syscall があります。fork を一般化したもので、親子でどのようなリソースを共有し、どのようなリソースを分けるかをフラグで細かく指定できます。現在の Linux では、fork も内部的には clone 系の仕組みで実装されています。この「何を分けるか」を指定するフラグが、コンテナの「隔離」にも使われることになります。詳しくは当日説明します。

### 実際に見てみる

`strace` を使うと、プロセスが呼び出した syscall を見られます。[開発環境](../environment/) で試してみてください。`strace` が入っていなければ、`sudo apt-get install -y strace` でインストールできます。

```sh
strace -f -e trace=execve,clone,clone3,wait4 sh -c 'ls > /dev/null'
```

出力は次のようになります（数字は環境によって変わります）。

```text
execve("/usr/bin/sh", ["sh", "-c", "ls > /dev/null"], ...) = 0
clone(child_stack=NULL, flags=CLONE_CHILD_CLEARTID|CLONE_CHILD_SETTID|SIGCHLD, ...) = 1964166
[pid 1964165] wait4(-1 <unfinished ...>
[pid 1964166] execve("/usr/bin/ls", ["ls"], ...) = 0
[pid 1964166] +++ exited with 0 +++
```

`sh` が起動し、`clone` で子プロセスを作ります。子プロセスの pid は、上記では結果的に PID 1964166 が割り振られました。次に、その子が `execve` で `ls` に置き換わり、親は `wait4` で子の終了を待っています。先ほどの syscall の説明とそのままの挙動をしています。
